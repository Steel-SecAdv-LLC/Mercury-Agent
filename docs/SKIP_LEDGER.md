# Skip Ledger

A skipped test reports as a pass. This page records, from the code, the two
kinds of skip that can hide a test for good, and CI fails when either appears
without being declared.

## Why it exists

The suite holds several hundred skip guards and nearly all are sound: a test
that needs torch skips where torch is absent and runs in the lanes that install
it. Two kinds are not sound, and neither shows in a green run.

**A test no lane can run.** `pytest.importorskip("x")` skips wherever `x` is
missing. If no extra installs `x`, that is every lane, and the test has never
executed. This is how the ledger started: `gymnasium` guarded
`tests/ml/test_ppo_trainer.py::test_gymnasium_vector_environments`, no extra
carried it, and the Gymnasium vector-environment interop of the PPO trainer had
never run in CI. `gymnasium` is now in the `[dev]` extra and the test runs.

**A test that is switched off.** `@pytest.mark.skip`, an unconditional
`pytest.skip(...)` and `@pytest.mark.xfail` park a test with no condition under
which it comes back.

## How it is measured

`scripts/measure_skip_ledger.py` reads `tests/` with `ast` (nothing is
imported, so it runs without the ML or native stack) and reads `uv.lock` for
the distributions the fullest test lane installs. For every `importorskip`
target it names the providing distribution and checks that the full lane
installs it, following dependencies and their extras through the lock.

```bash
python scripts/measure_skip_ledger.py                              # full report, with counts
python scripts/measure_skip_ledger.py --check docs/SKIP_LEDGER.md  # the CI gate
python scripts/measure_skip_ledger.py --update docs/SKIP_LEDGER.md # regenerate the block
```

The gate fails on:

- a guard on a dependency the full lane does not install;
- an `importorskip` whose module name is computed rather than written out (a
  lookup in a module-level table of names is resolved and accepted);
- an unconditional skip or an expected failure;
- a stale block below, or a declaration that no longer matches anything.

An exception is declared in the script (`ALLOWED_UNINSTALLED`,
`ALLOWED_PARKED`) with its reason, and the reason is printed in the block.

Counts that move with ordinary work (how many files guard on torch) are in the
plain report and are deliberately not in the block, so adding a guarded test
does not require regenerating this page. The block changes only when a new
optional dependency starts guarding tests or a test is parked.

## What it does not measure

- Whether a conditional skip's condition is ever true. A `skipif` on an
  environment variable that no workflow sets is out of its reach.
- Which lane runs a test, beyond "the full lane installs its dependency". The
  network lane (`MERCURY_NETWORK_TESTS=1`) and the `MERCURY_REQUIRES_*`
  session gates in `tests/conftest.py` cover that from the other side: they
  abort a lane whose declared dependency is missing instead of letting it skip.
